# mimic-JMP 实体贡献者许可协议（Corporate CLA）

> **CLA Version: 1.0**
> 生效日期：2026-11-26
> 项目自有代码许可证：`AGPL-3.0-or-later`
> 本文件的内容指纹（sha256）由 `.cla/signatures.json` 中每条实体签署记录的
> `agreementSha256` 锁定。**任何文字改动都必须升 CLA 版本并要求重新签署**。
>
> ⚠️ **本文为工程部署模板，不构成法律意见。** 正式启用前须由开源合规
> 律师定稿（尤其第 9 节主体信息与管辖法）。背景见
> `docs/DEVELOPMENT_PLAN.md` §7.7。

## 0. 当事方与定义

- **「公司」**：签署本协议的法人实体，包含其控制的、控制其的，或与其
  受共同控制的关联实体（参照 Apache-2.0 §1 对 *"Legal Entity"* 的定义）。
- **「授权代表」**：依法有权代表公司订立合同并使其受约束的自然人。
- **「员工提交者」**：公司列于附录 A 名单中、以公司名义或在工作范围内
  向项目提交贡献的雇员或受托人。
- **「贡献」**（Contribution）：定义与 `.cla/ICLA.md` §0 相同。
- **「项目维护方」**／**「项目许可证」**：定义与 ICLA §0 相同。

## 1. 签署与适用范围

1.1 由授权代表在 `.cla/signatures.json` 中提交一条 `type: "entity"` 的
签署记录，即视为公司签署本协议。记录必须包含公司名称、授权代表姓名、
签署时 CCLA 文本的 sha256，以及附录 A 对应的员工 GitHub 登录名。

1.2 本协议覆盖附录 A 所列员工提交者在**签署前后**以公司名义提交的全部贡献，
以及公司拥有版权、由任何第三方代其提交的贡献。

1.3 **CCLA 不替代个人 ICLA**：参照 Apache 基金会的做法，公司签署 CCLA
并不免除员工提交者个人签署 ICLA 的义务（个人 ICLA 覆盖公司不拥有版权的
那部分贡献）。PR 门禁对每位贡献者独立判定，见 §3.4。

## 2. 版权许可授权（核心条款）

2.1 公司在此向项目维护方授予一项**永久的、全球性的、非独占的、
免费的、免版税的、不可撤销的、可再许可的**版权许可，允许维护方及
其授权的第三方以源码或目标码形式，对公司贡献进行使用、复制、修改、
创作演绎作品、公开显示、公开表演、分发、**再许可（sublicense）**，
并允许维护方**以任何许可证（包括但不限于项目许可证、其他开源许可证、
商业或专有许可证）分发或授权包含该贡献的作品或其演绎作品**。

> English reference wording (Apache-2.0 §2, extended):
> *"a perpetual, worldwide, non-exclusive, no-charge, royalty-free,
> irrevocable copyright license to ... sublicense, and distribute the Work
> and such Derivative Works in Source or Object form"* —
> 本协议明确追加「可由项目维护方再许可、且不限制于特定许可证」。

2.2 公司**保留**对贡献的完整版权；本协议是许可授权而非版权转让。

2.3 该「可再许可」条款使项目未来采用 Open-core / 双许可 / 商业授权时
无需逐一取得公司重新同意；缺少该条款时，AGPL 项目改变许可证通常
需要全体版权持有人同意，实际上不可行。

## 3. 专利许可授权

3.1 公司在此向项目维护方及项目使用者授予一项永久的、全球性的、
非独占的、免费的、免版税的、不可撤销的（**除 3.2 外**）专利许可，
覆盖公司有权许可、且因公司贡献单独或与所提交作品结合而必然被侵犯的
专利权利要求。

3.2 **专利诉讼终止**：若公司（或其关联实体）对任何实体提起专利诉讼
（含反诉），主张项目作品或其中纳入的贡献构成直接或间接专利侵权，
则依据本协议授予公司的专利许可自起诉之日起终止。措辞参照
Apache License 2.0 §3。

## 4. 陈述与保证

公司声明并保证：

4.1 授权代表依法有权代表公司签署本协议并使公司受其约束。

4.2 公司拥有或已取得授予第 2、3 条许可所需的全部权利；员工提交者的
贡献如属职务作品，公司已通过雇佣或委托安排取得相应权利。

4.3 贡献中的第三方材料已标注来源、版权声明与许可证，且其许可证允许
按本协议使用与再许可。

4.4 公司将确保附录 A 名单中的员工提交者知悉并遵守本协议、
`CONTRIBUTING.md` 及 `.cla/ICLA.md`；名单变更须通过新的 PR 更新签署记录。

## 5. 无支持义务与免责

5.1 贡献按「现状」（AS IS）提供，公司无义务提供支持、维护或更新；
除本协议明确约定外，不提供任何明示或默示担保（含所有权、不侵权、
适销性及特定用途适用性）。

5.2 在法律允许的最大范围内，双方均不承担间接、附带或后果性损害赔偿
（参照 Apache-2.0 §7、§8）。

## 6. 生效、期限与版本

6.1 本协议自签署之日起生效，授权永久且不可撤销。

6.2 每条签署记录必须包含签署时 CCLA 文本的 sha256。修改文本必须提升
`CLA Version`；文本变更而版本未提升会被 `spike/scripts/cla_check.mjs`
判定为静默篡改并使门禁失败。

6.3 版本升级后，已作出的贡献继续受签署时那一版约束（不追溯扩张授权）；
新的贡献须签署新版才会被 PR 门禁接受。因此第 2 条的再许可授权
必须在第一版写足。

6.4 公司可书面通知项目维护方终止本协议的**未来适用**，但终止不影响
终止前已提交贡献的授权，也不影响终止前已分发版本的继续分发。

## 7. 商标与其他

7.1 本协议不授予使用项目名称、商标、服务标记的权利，
为合理描述贡献来源所必需的使用除外。

7.2 若任何条款被认定无效，其余条款继续有效。

## 8. 签署信息字段

`.cla/signatures.json` 中实体签署记录须含：

| 字段 | 说明 |
|---|---|
| `login` | 该公司在 GitHub 上的组织登录名或授权代表登录名 |
| `type` | 固定为 `"entity"` |
| `name` | 公司法定全称 |
| `email` | 公司联系邮箱 |
| `organization` | 公司法定全称（与 `name` 一致） |
| `authorizedBy` | 授权代表姓名 |
| `contributors` | 附录 A 员工 GitHub 登录名数组（见下） |
| `claVersion` | `"1.0"` |
| `signedAt` | ISO 8601 UTC 时间戳 |
| `method` | `offline-file` / `pr-comment` / `manual` |
| `evidence` | PR 编号、commit SHA 或线下签署凭据链接 |
| `agreementSha256` | 签署时 `.cla/CCLA.md` 的 sha256 |

> 注：`contributors` 是实体签署记录的可选扩展字段；
> `spike/scripts/cla_policy.mjs` 会校验其中每个登录名。

## 附录 A：被授权员工提交者名单

由公司在签署记录中以 `contributors` 数组登记，例如：

```json
"contributors": ["alice-dev", "bob-qa"]
```

名单变更须提交新 PR 更新签署记录；未列入名单的员工提交者
须以个人身份签署 `.cla/ICLA.md`。
